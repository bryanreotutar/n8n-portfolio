## Patterns used across all four

- **AI writes wording, code owns the facts.** Amounts, dates, links and IDs are inserted by JavaScript, never generated by the model. AI output is parsed and validated, and a rules-based or template fallback runs if it fails.
- **Idempotency.** Stable references (`CRM-DEAL-<id>`, `HLX-<number>`) are checked before anything is created, so a retried webhook can't double-bill.
- **Webhooks carry IDs only.** The workflow re-reads the record from the source system, so a forged call can't inject data.
- **Error handling.** Retries with back-off on API calls, error outputs routed to alerts, and an Error Trigger lane in every workflow.
- **Data minimisation.** In the healthcare suite, phones, emails and Medicare/NDIS numbers are replaced with tokens before any text reaches the LLM.

## Importing a workflow

1. In n8n: **Workflows → Import from File** → choose the folder's `workflow.json`.
2. Re-create the credentials listed in that folder's README (credential IDs are removed from the exports).
3. Replace any `__PLACEHOLDER__` values (they are listed in each README).

## About these exports

Credentials, API keys, webhook URLs, account IDs, email addresses and pinned test data have been removed and replaced with `__PLACEHOLDER__` values. Sample people and companies in the demo data are fictional.

Built with AI-assisted coding (Claude, ChatGPT, Gemini, Grok): AI drafts the code nodes, prompts and request bodies, and every output is checked and fixed by hand.
